# 后端全量功能 QA 问题报告

- 测试时间：2026-09-25
- 测试范围：认证 / 用户资料 / 签到 / 店铺 / 优惠券 / 秒杀（含并发与 Kafka 消费）/ 动态 / 点赞 / 关注 / feed / 上传 / RAG（11 接口）/ 安全边界
- 测试方式：`/tmp/qa.py` 全量脚本实测（58 项断言通过、5 项失败），复现均基于线上 `127.0.0.1:8081`
- 结论：**发现 6 个问题（5 个功能缺陷 + 1 个设计缺陷），已全部修复并复测**

## 问题清单与修复

### B1 店铺详情完全不可访问（严重）

- **现象**：`GET /shop/{id}` 对任何店铺都返回 `{"success":false,"errorMsg":"店铺不存在！"}`，前端店铺详情页不可用。
- **复现**：`curl /shop/1`（库中明明有 14 家店）。
- **根因**：详情只读 Redis 逻辑过期缓存，缓存未命中时直接返回失败、**缺少回源 DB 逻辑**；缓存从未被预热（原 Java 版依赖手工测试预热，Go 重写保留了该行为）。
- **影响**：店铺详情、附近店铺（后续 GEO）全链路不可用。
- **修复**：缓存未命中 → 回源数据库并写入逻辑过期缓存返回；DB 不存在 → 写入 2 分钟空值缓存（防穿透）并提示不存在；解析失败的脏缓存删除后回源。
- **状态**：✅ 已修复

### B2 附近店铺搜索（GEO）永远为空（严重）

- **现象**：`GET /shop/of/type?...&x=&y=` 返回空数组，即使库中有带坐标店铺。
- **根因**：`shop:geo:{typeId}` 索引从未写入；店铺新增/更新时未维护 GEO，也没有懒回填。
- **修复**：新增/更新店铺时 GEOADD（更新时同步旧类型集合清理）；查询时若 GEO 集合为空则从 DB 批量回填该类型带坐标店铺后再搜索。
- **状态**：✅ 已修复

### B3 图片上传失败 & 上传后可访问性（严重，三处子问题）

- **B3a 上传接口 500**：容器以非 root（uid 10001）运行，挂载卷 `/data/uploads` 属主为 root → 无写权限。
  - 修复：镜像内预建 `/data/uploads` 并 chown；部署脚本对已存在卷执行一次 chown。
- **B3b 图片 404**：前端把返回路径拼成 `/imgs/blogs/...` 由 nginx 静态服务，而后端写入 `/data/uploads/blogs/...`，两处不通。
  - 修复：compose 把上传卷只读挂载进 nginx，新增 `location /imgs/blogs/` 别名到卷内目录。
- **B3c 路径穿越（安全）**：`GET /upload/blog/delete?name=../../etc/hostname` 可删除上传目录之外的任意文件（原 Java 同款问题）。
  - 修复：删除前做路径规范化与包含性校验，越界返回「错误的文件名称」。
- **状态**：✅ 已修复

### B4 `POST /voucher`（普通券）错误地走秒杀逻辑（设计缺陷）

- **现象**：普通券接口与秒杀券接口完全同逻辑：都插入 `tb_seckill_voucher` 并预载库存；不带 stock 发布普通券直接 500（原 Java 遗留下的实现错误，被行为等价重写保留）。
- **正确行为**：`POST /voucher` 只插入普通券（`tb_voucher`）；`POST /voucher/seckill` 才建秒杀券（双表 + 库存预载，stock 必填）。
- **修复**：拆分两个服务方法与路由；同步更新 OpenSpec seckill spec。
- **状态**：✅ 已修复

### B5 删除知识库残留评估/问答数据（轻微）

- **现象**：`DELETE /rag/kb/{id}` 只级联清理切片/文档/任务，`rag_eval_run`、`rag_eval_case`、`rag_chat_log` 残留脏数据。
- **修复**：删除知识库事务内级联清理三类记录。
- **状态**：✅ 已修复

### B6 静态代码审查发现（非 QA 失败项）

- `POST /user/logout` 恒返回「功能未完成」：**保留原行为**（前端不依赖）。
- `POST /blog` 不关联店铺时会 500（`shop_id` NOT NULL）：与前端「必须选择服务点」的交互一致，暂按原行为保留。
- 热门榜/详情逐条查作者（N+1 查询）：数据量小，暂不优化，已记录。
